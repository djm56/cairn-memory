# Roadmap

_Status as of 2026-10-31: M1 (Server-mode MCP) is current. M2 (Server) is built; its live run (#19) is pending, so M2 is not passed. Phases 0 to 2 are done, and their exit checks passed. Live progress is on the [milestones](https://github.com/djm56/cairn-memory/milestones) and the [Cairn Memory Roadmap board](https://github.com/djm56/cairn-memory/projects)._

Plan v1 (2026-10-30) replaces the phase list with eight milestones and a Later set. The build runs from the outside in: the server-mode MCP adapter first, then the server, the web UI and dashboard, hooks and the CLI, the plugin, the import from bishop-memory, a pilot on one project, and the roll-out. Each milestone ends with an exit check that a reviewer can run. Version 1 is the scope of M1 to M8 ([PLAN.md §2](https://github.com/djm56/cairn-memory/blob/main/docs/PLAN.md#2-build-order), [PLAN.md §3](https://github.com/djm56/cairn-memory/blob/main/docs/PLAN.md#3-milestones)).

| Milestone | Was | What it delivers | Exit check | Status |
|---|---|---|---|---|
| M1 Server-mode MCP | Phase 3 | `cairn mcp` over the server only, with 13 tools plus recall and search; `cairn init`, `status`, `doctor`, `export task` and `hook session-start`; the `internal/api` handlers, with no network listener in the shipped binary | An MCP stdio test drives a small task flow through `cairn mcp`, `internal/client`, `internal/api` and `core` against an in-process test server; `cairn export task` prints the result | Current |
| M2 Server | Phase 5 | `cairn serve`: the listener over the M1 handlers, with TLS, body caps and `/healthz`; API keys with `agent`, `operator` and `viewer` scopes; backup; the directive cap and `review_by` | Conformance suite passes over HTTP; agent key refused on operator routes; viewer key refused on every write (tests); M1 flow works with `server` set; the live Claude Code run against `cairn serve` on another machine (#19), and `cairn export task` prints it | Built; live run pending |
| M3 Web UI + dashboard | Phase 6 | Pages for tasks, learnings, directives and projects; the dashboard | A lead sees a proposed finding, accepts it, ratifies a directive, and `task_current` returns it next session; a viewer key sees every page and gets 403 on every action | Planned |
| M4 Hooks + CLI | New | `pre-compact` and `stop` hooks; `cairn enable --agent`; the CLI with `--json`; `cairn doctor --agent` | On Claude Code a task started before `/compact` continues correctly after it with no user prompt; an agent with only bash completes and closes a task through the CLI | Planned |
| M5 Plugin | Phase 4 | The Claude Code plugin, its skill and hook reminders, the launcher, a local marketplace, plugin validation in CI, and an install guide | A new developer on a clean machine installs and records a task in 10 minutes from the guide, with no other instruction file | Planned |
| M6 Import | Phase 7 | `cairn import bishop-memory` with a dry run; idempotent; a counts report | Dry run on a copy maps every mission, step, event, finding, directive, criterion, lesson, mistake and deliverable, or names each skip; counts match; history visible on the dashboard | Planned |
| M7 Pilot | New | One pilot project, two developers, one operator; daily review of findings; a weekly look at the dashboard with a project manager | Two weeks of real tasks; every finding decided within 48 hours; five directives ratified; a project manager can answer 'what is running' from the dashboard alone | Planned |
| M8 Roll-out | Cut-over ([PLAN §5.3](https://github.com/djm56/cairn-memory/blob/main/docs/PLAN.md#53-cut-over)) | `.cairn.toml` in every active project; operator keys to leads, viewer keys to project managers; harnesses move between tasks; bishop-memory read-only, then archived | No harness writes to bishop-memory; backups verified by a restore to a scratch server | Planned |
| Later | Phases 8–10, Postgres | Scheduled review loop; per-harness plugins; public releases; Postgres store; documentation ingestion | Opened only after M8 | Planned |

The full table, with the work of each milestone in more detail, is in the [milestone table](https://github.com/djm56/cairn-memory/blob/main/docs/PLAN.md#milestone-table) in PLAN §3. The phases before Plan v1 (0 to 2) are history, and their exit checks are in PLAN §3 too.

## Two places, two jobs

- **Milestones and the board** hold live progress: which issues are open and what is in progress. The [milestones page](https://github.com/djm56/cairn-memory/milestones) and the [Projects tab](https://github.com/djm56/cairn-memory/projects) are where to look.
- **PLAN.md** holds the definitions: each milestone's work and its exit check. An exit check is what a reviewer runs to say a milestone is done. The table is in [PLAN §3](https://github.com/djm56/cairn-memory/blob/main/docs/PLAN.md#milestone-table).

The milestone descriptions are copies made from the exit checks in [PLAN §3](https://github.com/djm56/cairn-memory/blob/main/docs/PLAN.md#milestone-table), held in [roadmap.json](https://github.com/djm56/cairn-memory/blob/main/.github/roadmap.json). When the two differ, PLAN §3 is the authority, and the two are changed together. See [How we work](How-We-Work) for how the issues and board are set up.
